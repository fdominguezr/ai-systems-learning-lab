# Publication editing

For every new or revised technical article, series, README, photograph, diagram or chart in this repository, follow `docs/PUBLICATION_CHECKLIST.md` before declaring the delivery complete.

Run `python scripts/check_publication.py` and `python -m unittest discover -s tests -v`. Retain existing educational tests and license checks. A structural PASS is not visual, scientific or publication approval.

Review ALL affected uses of shared assets and all diagrams using a defective pattern. Inspect exported graphics and the intended page rendering at desktop and narrow/mobile width. Do not claim a real mobile-device test from a desktop viewport. Keep photo provenance, measurement limits and partial coverage explicit. Never invent missing time series or causal model rankings.

Update the compact root index whenever a series/article is added. Preserve public/private boundaries: no private chat transcripts, paths, credentials or internal learning records in this public repository.

Before changing any acceptance test, justify how it follows the current page's role; do not weaken checks merely to get green. After authorized publication, verify the destination commit and changed content. Report structural, visual, factual and publication status separately; UNKNOWN or pending checks prevent a blanket 'fully verified' claim.

Use the pull-request checklist for auditable scope. Direct commits require the same evidence in the delivery report. These instructions apply to agents reading this repository; they do not install instructions in existing ChatGPT chats or other repositories.
